## 实际坏图 34754 根因

浏览器发现《带螃蟹的早餐》占位后，按该 ID 获取唯一作品元数据，分别请求相同 640px WebP 的本地、公网及 COS 地址。公网与 COS 均返回 HTTP 400、XML `ImageTooLarge`；本地资源代理将该错误包装成 502。证据 `tests/image34754-diagnosis.json`。这是源资产超过云图像处理限制，不是路径编码或前端误占位，也证明此前 16 张全通过不能代表全库。

修复需要资产侧生成适合在线处理的派生缩略图并登记地址；不能由浏览器自动加载超大原图兜底。未下载原图、修改生产资源或写数据库。建议代理保留可观测的上游状态/错误分类，避免把永久资产错误当网络故障重试。

34754 派生资产排查：本地 cosbig.json 136 条映射中无此 ID；完整活页记录的 thumb/full 都是同一原始 JPG 加云转换，未发现现成 720px 派生地址。本地无 web/img 资产目录，不能据此证明远端所有桶都不存在文件；未枚举远端存储。

已提供 `scripts/prepare_image_derivative.py`：默认 dry-run，不联网、不上传、不写数据库；仅接受已有本地源文件，限制源 128 MiB/1 亿像素，输出最长边 720px/512 KiB，拒绝覆盖已有文件，生成 ID/尺寸/哈希清单。`--apply` 需要 Pillow；真实超限资产仍需可信本地源。回填步骤在 `docs/image34754-backfill.json`。
